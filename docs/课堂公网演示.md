# 课堂公网演示手册（Cloudflare Quick Tunnel）

用你自己的电脑当服务器，通过 Cloudflare Quick Tunnel 生成临时公网地址（`https://xxx.trycloudflare.com`），让同学在教室、宿舍或手机流量下直接打开网站模拟订票。

```
同学手机/电脑 ──HTTPS──> https://xxx.trycloudflare.com
                              │  Cloudflare 边缘
                              ▼
                    cloudflared（你电脑上运行）
                              │  本机回环
                              ▼
              Python Web 127.0.0.1:8080 ──docker exec──> MySQL / Neo4j / Redis（仅本机）
```

特点：

- 免域名、免公网 IP、免路由器端口映射，也不用登录 Cloudflare 账号；
- 自带 HTTPS，数据库端口（3306/7474/7687/6379）不会暴露到公网；
- 前端 API 是相对路径，换域名零改动；服务端保持监听 `127.0.0.1` 即可；
- URL 是临时的，重启 tunnel 会变——一节课的演示正合适，下课关掉即下线。

## 一、一次性准备（课前）

1. 安装 Cloudflare 的 `cloudflared`（PowerShell 中执行）：

   ```powershell
   winget install --id Cloudflare.cloudflared
   ```

   装完重开一个终端，确认 `cloudflared --version` 有输出。

2. 确认本机环境能按 [运行说明.md](运行说明.md) 正常启动：Docker Desktop、Python 3.11+、双击 `start.cmd` 出用户端页面。

3. 课前彩排一次完整流程（见下一节），确认能拿到 `trycloudflare.com` 地址并用手机流量打开。

4. 电源计划设为「永不睡眠」（设置 → 系统 → 电源），演示期间电脑不能休眠断网。建议插电 + 有线网络，手机热点做备份。

## 二、演示当天启动

在项目根目录双击 **`start-tunnel.cmd`**，或运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-tunnel.ps1
```

脚本会自动完成：

1. 检查 `cloudflared` 是否安装；
2. 若本机服务未启动，在**新窗口**拉起 `start.ps1`（Docker + 迁移 + Web），等 `/api/health` 就绪；
3. 启动 Cloudflare Quick Tunnel 并把公网地址**打印 + 复制到剪贴板**。

常用参数（与 `start.ps1` 一致，可组合）：

```powershell
.\start-tunnel.ps1 -Port 8090          # 8080 被占用时换端口
.\start-tunnel.ps1 -NoRedis            # 不启 Redis（自动退化为 MySQL 轮询）
.\start-tunnel.ps1 -SkipGraphSync      # 跳过 Neo4j 图同步
.\start-tunnel.ps1 -BookingWorkers 8   # 订票并发工作线程（默认 8，上限 8）
.\start-tunnel.ps1 -AdminPassword 'Demo@2026'   # 仅首次建管理员账号时生效
```

> `-AdminPassword` 只在**第一次**创建管理员账号时生效（库里已有 `admin` 后再传不会改密）。要在公开 URL 下用管理端，建议首次启动就带上它；已存在账号则课后自行在库中处理，或干脆不外发管理端链接。

## 三、发给同学的内容

用户端（发班级群）：

```
12306 模拟订票课堂演示：https://xxx.trycloudflare.com/
打开后输入你的名字即可登录，搜车次、下单、支付、退票都可以玩。
```

管理端（**只投屏在自己电脑上，不要发链接**）：

```
https://xxx.trycloudflare.com/admin-login.html
```

建议的演示节奏：

1. 同学各自用姓名登录，搜「城市 → 城市」查余票、下几单；
2. 你投屏管理端，看订单增长、库存座位图变化；
3. 高潮环节：管理端「AI 订票压测」，全班同时抢一趟车的最后几张票，展示位图防超卖、`FOR UPDATE SKIP LOCKED` 排队和候补队列；
4. 随手点开一张订单的动态电子车票收尾。

## 四、收尾

1. 在 tunnel 窗口按 `Ctrl+C`（公网地址立刻失效）；
2. 关掉服务窗口（`start.ps1` 那个）；
3. 数据都在本机 MySQL 里，下次 `start-tunnel.cmd` 会接着用；想清空重来再处理 `mysql84` 数据卷。

## 五、常见问题

| 现象 | 处理 |
|---|---|
| `cloudflared was not found` | 先执行 `winget install --id Cloudflare.cloudflared`，重开终端 |
| 等不到公网地址 / 打印 ERR | 看 tunnel 窗口红色日志；通常是网络被校园网拦截出站，换手机热点再跑一次 |
| 同学说打不开，但你本机能开 | 确认 tunnel 窗口还开着、URL 没换过；用手机流量访问 `https://xxx.trycloudflare.com/api/health` 看是否 `ok` |
| URL 变了 | Quick Tunnel 每次重启都会换地址，重新复制发群里即可（Named Tunnel 才能固定） |
| 服务窗口提示 8080 被占用 | `.\start-tunnel.ps1 -Port 8090` |
| 登录报 `sp_register_demo_account does not exist` | 初始 SQL 是 mysqldump（不含存储过程）。重跑 `start-tunnel.cmd` 会自动补跑 V004～V012；详见 [运行说明.md](运行说明.md) |
| Docker 里 mysql84 起不来，报 3306 bind 占用 | 本机 Windows 服务 MySQL80 占了 3306。项目已映射到 3307，拉最新 `docker-compose.yml` 后 `docker rm -f mysql84; docker compose up -d` 重建即可；详见 [运行说明.md](运行说明.md) |
| Docker 没起来 | 手动打开 Docker Desktop，等右下角鲸鱼图标就绪后重跑脚本 |
| 演示中途电脑断网 | tether 手机热点重跑 `start-tunnel.cmd`，把新 URL 重新发群 |

## 六、安全边界（课堂演示级）

- 公网 URL 知道就能进；乘客端本来就是「姓名直登」的演示登录，1~2 小时窗口内风险可控。
- 管理端有真正账号密码（默认 `admin / RailFlow@123`），**只在自己屏幕投屏**，不要发到群里。
- MySQL / Neo4j / Redis 只监听本机，不会因为 tunnel 暴露。
- 演示结束务必关掉 tunnel。

## 七、后续升级路径（本次不做）

拿到域名后可以演进成常驻演示站：

1. 域名托管到 Cloudflare → 建 **Named Tunnel**，固定 `demo.你的域名.com`；
2. 上 **Cloudflare Access**（One-time PIN / 学校邮箱验证）把外人挡在门外；
3. 需要时加 WAF Rate Limiting 防刷。
