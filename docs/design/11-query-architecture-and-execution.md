# V010 MySQL + Neo4j 组合查询设计与执行报告

## 1. 查询架构

系统采用“图数据库产生候选、关系数据库确认可售”的两阶段查询：

```text
用户查询
  ├─ 直达：MySQL 直接检索停站顺序、票价和实时位图
  └─ 换乘：Neo4j 枚举候选车次组合
              ↓ JSON 候选（最多 100 个）
           MySQL 批量复核时刻、票价和两程余票
```

MySQL 始终是列车运行实例、完整时间、票价、库存和订单的事实源。Neo4j 的结果只是可能路径，不能直接显示为“有票”，更不能参与扣减库存。

## 2. Neo4j 查询投影

原图的 `(:Station)-[:TRAIN_SEGMENT]->(:Station)` 保留，用于展示铁路运行网络。V010 另建：

`(:TrainRun)-[:CALLS_AT {station_order, arrival_at, departure_at}]->(:Station)`

正式图当前包含 1798 个 `TrainRun` 节点和 7626 条 `CALLS_AT`。`run_id` 唯一约束保证运行实例可准确回到 MySQL；`service_date` 索引限制单日查询范围。

相较于在数千条平行 `TRAIN_SEGMENT` 上做可变长度遍历，`TrainRun + CALLS_AT` 能直接表达同一列车先后停靠两个站，并自然连接两趟列车共同停靠的换乘站。

## 3. 直达查询

`sp_search_direct_trains` 输入：起终站、服务日、可选发车时间窗、乘车人数、A/B/C/D/F 偏好和是否允许兜底。

每个“运行实例 × 席别”结果包含：

- 车次类型、到发时间、历时；
- 起止站序和请求区间位图；
- OD 估算里程与票价；
- 总席位、动态余票、指定字母余票；
- 当前多人订单是否能够整单满足。

余票表达式直接读取 `train_run_seat.occupied_mask`，因此不会使用缓存中的过期数量。

## 4. 换乘候选与权威复核

Neo4j 返回 `firstRunId`、`secondRunId`、`transferStationId`。图查询先用停站顺序和字符串时间排除明显逆序候选，但不承担最终判断。

候选 JSON 传入 `sp_validate_transfer_candidates` 后，MySQL 再验证：

- 两趟运行实例均属于指定服务日且正在销售；
- 第一程为起点到换乘站，第二程为换乘站到终点；
- 完整 `DATETIME` 满足 15～240 分钟换乘窗；
- 两程分别存在开放票价；
- 两程席别分别统计动态区间余票和位置余票；
- 返回总价、总历时以及两程是否都能整单满足。

候选限制为 100 个，防止图侧返回规模失控。两程产品使用两个独立临时表，规避 MySQL 同一临时表不能在一条语句中重复打开的限制。

## 5. 查询与交易是否分离

逻辑上已经分离，物理上暂不拆库：

- 查询过程只读 `train_run`、`run_fare`、`train_run_seat`；
- 交易过程通过行锁修改 `train_run_seat`；
- Neo4j 是异步可重建的查询投影；
- MySQL 查询结果在返回瞬间只是快照，真正下单仍由占座事务再次判断。

课程规模下无需 MySQL 读写分离、Redis 余票缓存或 CQRS 消息总线。逻辑边界已经足够讨论一致性；以后压测证明主库读压力确实成为瓶颈，再考虑物理拆分。

## 6. 可运行文件

- `database/migrations/V010__query_routines.sql`：MySQL 权威查询过程；
- `app/sync_query_graph.ps1`：当前机器可直接运行的零额外依赖同步；
- `app/sync_query_graph.py`：使用 PyMySQL 与 Neo4j Driver 的跨平台同步版；
- `app/query_service.py`：直达 + 一次换乘 JSON 命令行服务；
- `app/requirements.txt`：Python 依赖版本。

本机 pip 因代理连接失败暂未安装两个 Python 驱动，因此本轮使用 PowerShell/Docker 同步，并分别执行真实 Cypher 与 MySQL 过程完成端到端数据流验收。该环境问题不影响 V010 数据库能力；后端接口阶段可在虚拟环境安装依赖后直接运行 Python 服务。

## 8. 一致性边界

Neo4j 同步短暂落后不会导致超卖：最坏情况是候选缺失或包含已经变化的车次，MySQL 复核会过滤无效候选；下单事务还会再次锁定具体座位并检查位图。任何查询结果都不等于库存预留。
