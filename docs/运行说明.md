# CR12306 运行说明

## 最简单的启动方式

1. 安装并启动 Docker Desktop。
2. 在项目根目录双击 `start.cmd`。
3. 等待窗口显示 `CR12306 is ready`，并保持该窗口开启。
4. 浏览器访问：
   - 用户端：http://127.0.0.1:8080/
   - 管理端：http://127.0.0.1:8080/admin-login.html
   - 健康检查：http://127.0.0.1:8080/api/health

管理端初始账号为 `admin`，初始密码为 `RailFlow@123`。停止系统时回到启动窗口按 `Ctrl+C`。数据库容器可以继续运行，下次会复用已有数据。

## PowerShell 启动

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

脚本会自动启动或复用 MySQL、Neo4j、Redis，等待数据库健康，补齐迁移，在图数据库为空时重建查询图，并自动查找 Python 后启动 Web 服务。首次运行需要下载 Docker 镜像，可能需要几分钟。

## 常见问题

### 登录报 `PROCEDURE CR12306.sp_register_demo_account does not exist`

`db-init/CR12306.sql` 是 `mysqldump` 导出（默认不含存储过程），只建表不建过程。现在的 `start.ps1` 会检测到这一点并自动补跑 V004～V012（含座位与票价生成），无需手工处理。若自动修复仍失败，按提示删掉 `mysql-data` 卷后重跑一次即可。

### 3306 端口被占用（MySQL 容器起不来）

报错形如 `ports are not available: exposing port TCP 0.0.0.0:3306 ... bind: Only one usage of each socket address`，通常是因为本机装过 Windows 版 MySQL（服务名 `MySQL80`）。项目已把 Docker 内 MySQL 映射到宿主机 **3307**（`docker-compose.yml`），与本机 MySQL 互不干扰：

- 主服务经 `docker exec` 访问容器内 MySQL，不依赖宿主机端口，3307 即可；
- 若确需停掉本机 MySQL 腾出 3306，管理员 PowerShell 执行 `Stop-Service MySQL80; Set-Service MySQL80 -StartupType Manual`（会影响你其他用到 MySQL 的作业）。

### 8080 端口被占用

如果占用者是本项目，脚本会提示系统已运行。若被其他程序占用，可换端口：

```powershell
.\start.ps1 -Port 8090
```

随后访问 `http://127.0.0.1:8090/`。

### 对外开放给同学（公网）

双击根目录的 `start-tunnel.cmd`，会通过 Cloudflare Quick Tunnel 生成临时公网地址。详见 [课堂公网演示.md](课堂公网演示.md)。

### 暂时不使用 Redis

```powershell
.\start.ps1 -NoRedis
```

系统仍能运行，订票任务会退化为 MySQL 队列轮询。Redis 只负责高并发下的快速唤醒和削峰，MySQL 的 `booking_request_buffer` 才是可靠、可恢复的任务记录，所以 Redis 重启不会丢失请求。

### Python 命令无法使用

本机 Python 位于 `C:\Users\Lenovo\.local\bin\python3.12.exe`，只是没有加入 PATH。启动脚本已能自动找到它，无须手工执行 `python app/server.py`。

### 检查数据服务

```powershell
docker exec mysql84 mysqladmin -uroot -p123456 ping
docker exec neo4j-12306 cypher-shell -u neo4j -p 12345678 "RETURN 1;"
docker exec redis-12306 redis-cli PING
```

预期分别看到 MySQL 存活、Neo4j 返回 `1`、Redis 返回 `PONG`。

## Redis 与高并发设计

当前订票链路采用“Redis 加速、MySQL 兜底”的双层结构：

1. HTTP 请求先把任务可靠写入 MySQL 的 `booking_request_buffer`；
2. 写入成功后向 Redis 列表发送唤醒信号；
3. 后台线程由 Redis 阻塞读取立即唤醒，再从 MySQL 事务领取任务；
4. 多线程通过 `FOR UPDATE SKIP LOCKED` 并行领取互不冲突的任务；
5. Redis 不可用时自动回退到 MySQL 短轮询；
6. 座位分配仍受 MySQL 事务和唯一约束保护，防止超卖和重复占座。

这样既能吸收瞬时流量，又不会把订单可靠性依赖在缓存上，复杂度也保持在课程项目易于说明和演示的范围内。
