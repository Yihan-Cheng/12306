## 1. 安装内容

### 函数

- `fn_segment_mask(from_order, to_order)`：生成左闭右开区间的 63 位以内掩码。

### 存储过程

- `sp_query_availability`：按运行实例、OD、席别查询全程精确可用席位；
- `sp_create_order_hold`：为 1 至 5 名乘车人原子创建订单和支付占座；
- `sp_confirm_order_payment`：幂等确认支付，HOLD 转为 CONFIRMED；
- `sp_cancel_unpaid_order`：幂等取消未支付订单并准确释放原区间。

### 对账视图

- `v_inventory_reconciliation`：比较当前席位位图和有效分配掩码；
- `v_order_amount_reconciliation`：比较订单总额和订单项价格快照之和。

正式库现有视图总数为 3，加上此前的 `v_train_run_stop`。

## 2. 关键实现决策

- 存储过程使用 `READ COMMITTED` 和显式锁；
- 对 `train_run` 使用 `FOR SHARE`，多个购票事务不会因运行实例行而全部串行；
- 对最终候选 `train_run_seat` 使用 `FOR UPDATE`；
- 同一事务内按 `seat_id` 升序选择席位；
- 位图更新仍带重叠条件，影响行数不为 1 时整体回滚；
- 多人订单任何一人分配失败，整单回滚；
- `(user_id, idempotency_key)` 唯一约束处理同时到达的重复请求；
- 相同幂等请求并发时返回同一个订单，而不是生成两单；
- 支付回调通过 `payment_request_no` 唯一并幂等；
- 取消释放前检查目标掩码确实存在，防止重复释放误清其他订单的 bit；
- 订单、分配、位图和审计事件在同一数据库事务内提交。

## 3. 临时库功能测试

测试使用一趟 4 站、3 区间、2 个席位的最小编组。

### 区间掩码

| 区间 | 结果 |
|---|---:|
| 1→3 | 3，即二进制 `011` |
| 3→4 | 4，即二进制 `100` |
| 2→4 | 6，即二进制 `110` |
| 1→4 | 7，即二进制 `111` |

### 非重叠区间复用

同一席位依次分配 `1→3` 和 `3→4`：

```text
000 → 011 → 111
```

取消 `1→3` 后：

```text
111 → 100
```

后一订单的 `3→4` 区间没有被误清除。

### 幂等并发

两个会话同时提交相同用户、相同乘车人和相同幂等键：

- 两个会话都成功返回；
- 返回相同 `order_id=1`；
- 数据库中只有一笔订单和一个订单项。

### 最后一席竞争

两个不同用户同时竞争最后一个全程席位：

- 一个会话成功；
- 一个会话返回 `ORDER_INSUFFICIENT_INVENTORY`；
- 成功订单数量为 1；
- 有效全程分配数量为 1；
- 无超卖。

### 多人整单回滚

只剩一个全程席位时提交双人订单：

- 返回 `ORDER_INSUFFICIENT_INVENTORY`；
- 对应订单数量为 0；
- 临时分配的第一个席位也被事务回滚；
- 位图保持原值。

### 支付与取消

- 重复支付请求两次均返回同一个 `payment_id`；
- 支付确认不改变已占用位图；
- 取消未支付订单只清除其自身区间；
- 库存对账差异为 0；
- 金额对账差异为 0。
